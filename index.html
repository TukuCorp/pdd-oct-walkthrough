What a Verra PDD specialist experiences

Three questions that matter to a carbon-markets specialist who is not an AI engineer: first-hour setup, Verra compliance safety, and whether the new calculation workflow actually checks ER math.

A · First-hour experience

10+ terminal commands before a first draft

Before drafting a single PDD sentence, a staff member must unzip 673 MB, install Python, LibreOffice, Poppler, and an AI app, run 4 setup commands and 6–7 verification commands (~3 min of terminal logs), read 6+ markdown guides, run a startup smoke test, send Prompt A, review a checkpoint, and only then send Prompt B.

"Run the complete tests with the receiving device's approved workspace interpreter: python -m unittest discover..." (PORTABLE_UPDATE_2026-10-28.md)

  • Conflicting guides: Both Word setup guides in Drive are unchanged from 17 Sep 2026 (still skip Section 1, cite "pages 5 to 7", and omit all Oct 28 Excel tools).
  • Scary false alarms: Even on a working laptop, setup prints soffice_version=UNAVAILABLE (timed out after 15 seconds), looking broken when PDF rendering actually works.
  • Duplicate folders: 4 WTE projects appear twice in inputs/fresh_registry/, and 3 copies of the v4.4 PD template still ship.
B · Verra methodology & VVB risk

Missing VCS Standard v4.7 & VM0043 v1.0

The library matches Gaotang WTE's ACM0022 v03.0, but misses two rules that Verra Project Review Reports explicitly enforce on the shipped projects:

  • CarbonCure (VCS 4019): Registered and verified under VM0043 v1.0 (confirmed in PRRs R1, V2, V3), yet library/ ships only VM0043 v1.1 (Dec 2024). Applying v1.1 clauses to a v1.0 project without an approved transition triggers a VVB Corrective Action Request (CAR).
  • No VCS Standard anywhere: Both CarbonCure and Gaotang are assessed against VCS Standard v4.7 (Apr 2024), which is absent from library/. Staff cannot verify excluded activities (Table 1), crediting-period rules (Section 3.8.1), safeguards, or v4.3-to-v4.4 template migration rules inside the workspace, risking Verra completeness-check rejections.
C · New calculations/ workflow

Builds new models, does not verify proponent files

calculations/ is a separate workflow to author a new Calculations.xlsx from project parameters. It does not recalculate or independently verify a proponent's existing ER sheet.

"It creates calculations; the PDD workflow continues to report supplied calculations without recalculating them." (calculations/README.md)

  • Rounding (ROUNDDOWN): Internal design notes (EXCEL_EXAMPLES.md) rightly spot Gaotang's ROUNDDOWN and Taiping's component-level rounding, but never explain in plain staff language why whole-tonne conservative truncation prevents VCU over-issuance.
  • Empty saved values: Docs rightly forbid opening and resaving workbooks with missing calculated values, but explain it in programmer terms ("cached formula values", "ABSENT") instead of plain advice: ask the proponent for a properly saved Excel file.

Key findings for staff and reviewers

Issues that affect a Verra PDD specialist's daily work. Script-level engineering details sit in the collapsible section below.

Blocker New

F1 · Older .xls WTE spreadsheets fail every shipped Excel tool

WhatFour shipped WTE workbooks (Linfen VCS 4818 and Yixian VCS 5040) use the older binary .xls format. Every shipped Excel tool skips or rejects them, and the setup installs no .xls reader.

EvidenceExtracting any cell from ER-Linfen-4818-1st Ver.xls exits with an error; the manifest inspector reports only {"format": "xls"} with no sheets, formulas, or saved values.

FixBundle a read-only .xls reader (xlrd) in setup and support .xls in all three workbook tools.

Defect Partial (B1)

F2 · 183 MB workbook times out (>5 min) and slows every final check

WhatThe new Excel inspector handles the 111 MB CarbonCure file in 4.2 min without crashing, but timed out past 5 min on the 183.4 MB file. Because the final PDD checker re-scans every marked-read workbook from scratch on every run, checking CarbonCure takes over 11 minutes.

EvidenceMeasured runtimes: 56.9 s (19 MB), 254.6 s (111 MB), timeout at 300 s (183 MB).

FixSave a temporary inspection cache keyed by file fingerprint so repeat checks finish in seconds.

Defect Still open (D4/D5)

F7 · Missing VCS Standard v4.7 & VM0043 v1.0, duplicate WTE folders, and 3 template copies

Whatinputs/ and library/ did not change from September. VCS Standard v4.7 and VM0043 v1.0 are missing (VVB CAR risk on CarbonCure and v4.7 projects); inputs/pdd_examples/ is empty; three copies of the v4.4 PD template still ship; and four WTE projects appear twice in inputs/fresh_registry/.

EvidenceFile inventory and PDF version scans of CarbonCure PRRs (v1.0 / v4.7) and Gaotang PD (ACM0022 v03.0 / v4.7).

FixAdd VCS Standard v4.7 and VM0043 v1.0 to library/, remove duplicate WTE folders and legacy template copies, and populate or remove inputs/pdd_examples/.

Defect Still open (P6)

F6 · Word setup guides in Drive are unchanged from 17 September

WhatBoth Word guides in Drive still skip Section 1, cite "pages 5 to 7", and never mention the Oct 28 calculation workflow, Excel tools, strict Python setup, or 200 DPI QA. Non-AI staff following the Word guide miss the entire Oct 28 update.

EvidenceDrive modified dates are both 2026-09-17; zero mentions of Oct 28 tools in either document.

FixRebuild both Word guides from the Oct 28 markdown docs and add a one-page plain-English quick start.

Defect Partial (D2/P1)

F3 · Setup checker still hangs 15 s on LibreOffice version check on Windows

WhatEven though the guide warns not to rely on soffice --version, the setup script still runs it and prints UNAVAILABLE (timed out after 15 seconds) on Windows, alarming staff even when PDF conversion works.

EvidenceObserved 15 s timeout on every run of check_portable_pdd.py while the isolated PDF/PNG smoke test passed.

FixRead LibreOffice's version from its local version.ini file on Windows instead of running soffice --version.

Defect Partial (N2)

F4 · Dark-header contrast check misses default black text in Word

WhatThe new contrast check catches table headers where black text is set directly on the words, but misses headers that inherit default black from Word's Normal style on a dark navy fill.

EvidenceProbe on two navy (#2B3957) header cells: explicit black flagged at 1.83:1; style-inherited black passed with 0 warnings.

FixCheck the effective inherited text color (defaulting to black on dark fills), not only direct run formatting.

Defect New + D1

F8 · Word editability check stalls command-line AI tools

WhatTo clear QA_PENDING, the checker requires confirming the final DOCX was opened in an editable Word view. Command-line AI agents cannot open Word, so runs either stay stuck until a human signs off (undocumented) or agents rubber-stamp the box.

Evidencescripts/review_records.py:314-317 requires docx_opened_for_editability_check: true.

FixLabel the Word editability check explicitly as a human reviewer sign-off step in the run prompts.

Technical notes for Tinh (script-level fixes: F5, F8-path, F9, F10, F11)

F5 (Defect · New) — Top-level docx import crash: scripts/check_portable_pdd.py:15 runs from docx import Document before line 129 checks installed packages via find_spec. Staff running the checker before pip install see a raw traceback. Fix: move the import inside functional_smoke().

F8-path (Defect · D1 still open) — --report locked to outputs/: scripts/check_authored_pdd.py:392 still rejects --report under tmp/, inconsistent with audit_portable_pdd.py and extract_xlsx_evidence.py. Fix: allow tmp/ as well as outputs/.

F9 (Polish · New) — 3 new scripts omitted from audit: scripts/extract_xlsx_evidence.py, calculations/tools/inspect_workbook.py, and test_inspect_workbook.py are in PORTABLE_MANIFEST.json but missing from CANONICAL_FILES in scripts/audit_portable_pdd.py:27-69. Also align Poppler discovery (native/poppler fallback) with check_portable_pdd.py:138-139.

F10 (Polish · New) — Full-sheet XML scan on top-row reads: scripts/extract_xlsx_evidence.py:165-171 took 47.4 s to read Sheet0!A1:AR2 from the 19 MB workbook because ElementTree.iterparse scans all 3.2M cells after rows 1–2 are already found. Fix: break out once all target cells for the sheet are collected.

F11 (Polish · P2 still open) — Upstream PDF index warnings: Two CarbonCure registry PDFs still emit pypdf warnings (invalid pdf header, incorrect startxref pointer) before recovering text. Fix: note known upstream Verra warnings in inputs/README.md.

F2 detail — XML streaming bottleneck: scripts/source_manifest.py:240-244 re-runs inspect_source_structure() on every READ file during validate_source_manifest(). Switching to lxml.etree.iterparse or caching by (path, bytes, sha256) under tmp/ eliminates the 11+ min CarbonCure validation stall.
